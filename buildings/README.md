# 회관

`TownHall.tscn`은 3×3칸 본진용 회관 외형입니다. 석조 기단과 계단, 목조 벽, 푸른 슬레이트 지붕, 종탑, 깃발로 구성합니다. 시각 메시 전체가 X/Z -1.5~1.5 안에 들어가며, 바닥은 Y=0, 최대 높이는 약 4.345입니다. 정면과 입구는 -Z 방향입니다.

- `Visual`: 재질별 표면을 합친 정적 메시. 재질의 `banner`는 깃발과 문장을, `roof/roof_mid/roof_light`는 지붕을 표시합니다.
- `SelectionArea`: 물리 레이어 4(값 8)의 3×3 선택 영역입니다. 기존 유닛 선택 입력에는 아직 연결하지 않았습니다.
- `Entrance`: 입구 중심 표시점입니다. 유닛 생성 위치는 건물 점유 칸 밖에서 별도로 정해야 합니다.
- 루트의 `footprint` 메타데이터: Vector2i(3, 3).

`previews/TownHall.tscn`을 열고 F6으로 실행하면 서버 없이 볼 수 있습니다. 좌클릭 드래그로 회전하고 휠로 확대합니다. 바닥 격자는 1×1이며 금색 테두리는 3×3 범위입니다.

맵 원점이 칸 모서리를 뜻할 때, 시작 칸 (cx, cz)의 회관 중심은 `(originX + (cx + 1.5) * cellSize, 0, originZ + (cz + 1.5) * cellSize)`입니다. 현재 한 칸은 1단위이므로 기본 스케일 그대로 배치합니다. 양쪽 본진이 중앙을 향하게 하려면 각각 Y축 회전을 적용하세요.

게임에서는 `Main/Buildings`의 `BuildingManager`가 서버의 `BUILDING type id sideId x z yaw` 메시지로 회관을 생성합니다. `type=0`은 회관, `yaw`는 라디안입니다. `sideId`는 맵 본진 순서(왼쪽 1, 오른쪽 2)이며 접속한 플레이어 ID가 아닙니다. 왼쪽은 파란 깃발, 오른쪽은 빨간 깃발을 표시합니다. 각 인스턴스의 재질만 바꾸므로 공유 메시에는 영향을 주지 않습니다.

`WORLD_READY` 이후 받은 건물만 표시하며 동일한 ID는 재생성하지 않고 상태를 갱신합니다. `MAP` 재동기화 시 기존 건물을 비우고 새 스냅샷으로 복원합니다. 공통 `REMOVE id`는 해당 건물만 즉시 제거합니다. 본진 생성과 유지는 서버가 결정하고, 클라이언트는 접속이나 재접속 시 자체적으로 본진을 만들지 않습니다.

현재 기본 맵의 본진 좌표 `(-65, 0)`, `(65, 0)`에 그대로 배치하고 입구가 중앙을 향하도록 회전합니다. 이 좌표는 현재 격자의 칸 경계에 있으므로, 추후 정확한 3×3 칸 점유를 구현할 때는 위 중심 좌표 공식에 맞춰 맵 본진 좌표도 정렬해야 합니다. 건물 선택 입력·공격·생산·통행 차단과 실제 입구에서의 자원 반납은 아직 연결하지 않았습니다.

서버 `HP id current maximum`으로 회관 위 체력바를 갱신합니다. 초기 체력은 서버에서 1,000으로 지정하며, 클라이언트에서 추측하지 않습니다. 공통 표시 코드는 `ui/HealthBar.cs`, 자세한 동기화 방식은 `docs/health-bars.md`를 참고하세요.

재생성: C# 프로젝트 빌드 후 프로젝트 루트에서 `Godot --headless --path . --script tools/build_town_hall.gd`를 실행합니다. `TownHall.tscn`과 `meshes/TownHall.res`를 덮어쓰며 모델의 3×3 경계를 검사하고 `Building.cs` 연결을 유지합니다. 디자인 치수와 색은 생성 스크립트에서 수정합니다.

연결 확인: `Godot --headless --path . res://tests/BuildingSceneChecks.tscn`으로 서버 메시지 경로, 중복 스냅샷, 진영 색 분리, 잘못된 데이터, 삭제, 재접속을 확인합니다.
