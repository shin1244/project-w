# Project W

Godot .NET 클라이언트 프로토타입입니다. Go 서버가 유닛을 생성하고 이동을 계산하며, 클라이언트는 서버 상태를 표시합니다.

유닛 이동은 서버 30Hz 기준 1.5틱(50ms) 지연 보간합니다. 모든 유닛이 같은 재생 시점을 사용하며, 패킷이 늦으면 마지막 확정 위치에서 기다립니다. [이동 보간과 메시지 형식](docs/units.md#이동-보간)을 참고하세요.

`WELCOME id 편 COMMANDER`는 RTS 정보창, `WELCOME id 편 HERO 영웅종류`는 가운데 하단의 AOS 스킬 패널을 표시합니다. 늑대는 Q키나 Q 버튼을 누른 뒤 적 유닛을 클릭하면 물어뜯기를 사용합니다. 대상 지정 중에는 늑대 주변에 사거리 원을 표시합니다. Esc·우클릭으로 대상 지정을 취소하며, 스킬마다 서버 기준 남은 재사용 시간을 표시합니다. 패시브는 항상 적용되고, W는 다음 일반 공격 흡혈, E는 주변 지속 피해, R은 아군 미니언·용병을 먹는 포식입니다. 맵·미니맵은 공유하고, AOS의 오른쪽 명령창은 208×160 간단 정보 패널로 바뀝니다. 기본은 내 영웅이며 다른 유닛을 클릭하면 그 유닛의 체력과 능력치를 표시합니다. 내 영웅의 레벨·경험치바는 서버의 EXP 수신값으로 갱신합니다.

경기 시작 시 내 영웅 또는 본진을 가까이 보여주며, 상단에는 진영·역할·경과 시간·승리 목표와 조작 안내가 표시됩니다. 영웅 모드에서는 지휘관 전용 자원·인구 UI와 수신하지 않은 마나를 숨깁니다. 미니맵의 내 영웅은 밝은 큰 표식으로 구분합니다. 다친 유닛은 선택하지 않아도 체력바를 표시하지만, 안개로 숨겨진 유닛의 정보는 표시하지 않습니다.

사망 시 `RESPAWN 부활틱`과 서버 `TICK`으로 남은 초를 표시합니다. 부활 예정 시간이 지나도 새 영웅이 생성되지 않았다면 부활 위치 확보 중으로 안내하며, 실제 UNIT 수신 후 정상 상태로 돌아갑니다. 스킬 대상 지정·기절·침묵·체력 위험도 영웅 패널에 안내합니다.

## 승패와 AI 연습

처음 배치된 적 본진 회관을 파괴하면 승리합니다. 같은 틱에 양쪽 본진이 파괴되면 무승부입니다. 경기 종료 즉시 조작·전투·생산을 멈추고 결과와 플레이 시간을 표시합니다. 결과 화면의 **로비로 돌아가기**로 새 경기를 시작합니다.

AI 지휘관은 나무 채집, 일꾼 충원, 합숙소·병영 건설과 기사·궁수 생산을 맡습니다. 병력은 라인을 따라 진격하며, 본진 근처의 적에 대응하고 불리한 교전에서 후퇴합니다. 궁수는 근접 적과 거리를 벌리고, 늑대·골렘 영웅은 사거리·쿨다운·적 밀집도에 맞춰 기술을 사용합니다. 늑대 봇은 아군 미니언만 먹으며 플레이어의 일꾼·병력은 먹지 않습니다.

현재 AI는 0.4초 간격으로 판단하는 규칙 기반 봇이며, 자원·시야·능력치 보너스가 없습니다. 기본 연습용으로, 여러 라인 운영·빌드 다양화·사람 상대 실력 조정은 아직 제한적입니다. 학습형 AI나 Pluto를 탑재한 것은 아닙니다.

## 폴더

```text
game/             메인 게임 장면, 입력·통신 연결과 메시지 분기
lobby/            로비 서버 매칭·실제 전장 로딩
input/            마우스 입력과 맵 카메라
network/          TCP 연결과 명령 문자열
units/            UnitManager, 공통 유닛 스크립트와 일꾼·기사·궁수 씬
resources/        ResourceManager, 자원 공통 스크립트와 나무 외형 3종
buildings/        회관·요새·저장소·합숙소·병영·대장간·포탑 씬, 공통 공사 부지 표시
maps/             맵 장면과 서버와 공유하는 격자 데이터(test.json)
  resources/      지형 메시와 충돌 리소스
previews/         서버 없이 보는 맵·유닛 미리보기
tools/            맵 생성 도구
tests/            유닛·입력·맵 검증
docs/             설명과 미리보기 이미지
```

각 스크립트 옆의 `.uid`는 Godot의 리소스 식별 파일입니다. 스크립트와 함께 유지합니다. `.godot/`은 자동 생성 캐시이며 Git에서 제외합니다.

## 실행

1. Godot .NET에서 `project.godot`를 엽니다.
2. C#을 빌드하고 F5로 실행하면 `lobby/Lobby.tscn`이 열립니다. 로비 서버 주소를 입력하고 매칭을 시작합니다. [지인 테스트 실행·Pi 배포 안내](docs/friend-test.md)를 참고하세요.
3. 일반 매칭은 2명이 모이면 15초 뒤, 4명이면 즉시 시작합니다. 1팀 지휘관·영웅부터 배정하고 빈자리는 AI가 맡습니다. **혼자 연습 · 영웅/지휘관**을 고르면 AI 3명과 시작합니다. 두 모드 모두 로비 서버 연결이 필요합니다. 모든 사람의 맵 동기화가 끝나면 함께 시작하며 큐·로딩에서 취소/Esc로 돌아갈 수 있습니다.
4. 실제 전장을 실행하려면 Go 서버를 `127.0.0.1:7777`에서 실행합니다. RTS는 `game/Main.tscn`, AOS는 `game/AOS.tscn`을 열어 F6으로 실행합니다. AOS는 같은 전장을 상속하며 `MAP_READY <해시> HERO 200`으로 임시 영웅을 요청합니다. Main 루트의 `RequestedRole`·`RequestedHeroType`으로 접속 요청을 바꿀 수 있고 실제 역할·진영은 서버의 WELCOME으로 확정합니다. 내 유닛 좌클릭으로 단일 선택, 드래그로 여러 유닛 선택, 우클릭으로 이동·공격·채집·이어 짓기를 요청합니다.

첫 영웅(200)은 사족보행하는 돌연변이 늑대입니다. 오른쪽 옆구리의 작은 팔 하나, 긴 주둥이·송곳니·날카로운 갈기와 군데군데 드러난 뼈로 구분하며 별도의 모델·초상화·보행·물기 연출을 사용합니다. 서버의 UNIT/POS/STATE/HP/STATS와 기존 타입 번호는 그대로 사용합니다. AOS 체력바는 내 영웅의 HP를 표시합니다. 현재 서버에는 마나 수치·메시지가 없어 마나바를 숨깁니다.

외형은 `previews/MutantWolf.tscn`을 F6으로 열어 세 시점에서 확인합니다. Space는 걷기, A는 물기, Q는 돌진 자세, R은 회전, T는 진영색 전환입니다. [영웅 미리보기](docs/images/mutant-wolf.png).

늑대 **W · 피의 송곳니**는 다음 일반 공격으로 실제 깎은 체력의 50%를 회복합니다(재사용 8초). 공격 명중까지 대기하며 Q/E는 소모하지 않습니다. 보호막 피해·초과 피해는 회복에 포함하지 않고 최대 체력을 넘지 않습니다. **E · 피의 안개**는 5초 동안 늑대를 따라다니는 반경 3.5m 영역에서 매초 현재 공격력의 30% 피해를 줍니다(총 5회, 재사용 12초). W/E 모두 키나 버튼을 누르면 바로 발동합니다. 분홍 고리는 W 대기, 붉은 영역은 E 활성 상태이며 하단에도 남은 효과를 표시합니다. W/E 상태는 서버 `WOLF id 흡혈대기 E종료틱`으로 동기화되어 안개 재등장 시 복원되고 사망·부활 시 초기화됩니다. 늑대 W도 카메라 이동과 겹치지 않습니다.

두 번째 영웅(201)은 **룬 골렘**입니다. 로비의 영웅 선택에서 고르면 영웅 역할로 배정될 때 적용됩니다. 돌주먹·청록색 룬 심장·진영색 어깨판, 관절 보행과 주먹 공격, 보호막·충격파 효과를 사용합니다. 패시브 돌가죽은 받는 피해를 10% 줄입니다.

| 키 | 기술 | 효과 | 재사용 |
| --- | --- | --- | --- |
| Q | 내려찍기 | 주변 3.5m의 적에게 공격력 150% 피해, 2초간 35% 둔화 | 6초 |
| W | 돌갑옷 | 4초간 최대 체력 25% 보호막 | 12초 |
| E | 바위 돌진 | 적 클릭 후 돌진, 공격력 100% 피해와 0.6초 기절. 장애물에 막힘 | 10초 |
| R | 지진 | 주변 5m의 적에게 공격력 250% 피해와 1.25초 기절 | 30초 |

Q/W/R은 누르면 바로 사용합니다. E로 붙은 뒤 Q, 위험할 때 W, 적이 모이면 R을 쓰면 됩니다. 골렘의 Q/W는 스킬 전용이므로 카메라는 방향키·가운데 드래그로 움직입니다. `previews/RuneGolem.tscn`을 F6으로 실행하면 서버 없이 모델과 스킬 연출을 볼 수 있습니다(Space 걷기, A 주먹, Q/W/E/R 기술, Y 회전, T 진영색). [룬 골렘 미리보기](docs/images/rune-golem.png). 서버와 클라이언트를 함께 갱신해야 선택과 스킬이 적용됩니다.

AOS에서는 내 영웅이 생성되면 자동으로 조종 대상으로 고정됩니다. 별도 선택 없이 우클릭·미니맵 우클릭으로 이동하고 적 우클릭으로 공격합니다. A/S/D도 같은 영웅을 조종하며 빈 곳·다른 유닛·건물 클릭이나 드래그로 해제되지 않습니다. 다른 유닛을 좌클릭하면 오른쪽에 초상화·이름·체력·행동·공격력·사거리만 표시하며 명령 대상은 바뀌지 않습니다. 조회 대상이 죽거나 시야에서 사라지면 정보를 비웁니다. 내 영웅의 사망·시야 이탈·소유권 상실 시 명령을 멈추고, 다시 생성되면 자동으로 연결합니다. RTS는 기존 수동 선택과 명령창을 유지합니다.

로비와 로딩은 `lobby/MatchScreen.tscn` 레이아웃을 공유하며 `network/MatchSession.cs`가 큐와 입장 정보를 유지합니다. 게임 서버는 판마다 새 프로세스로 실행합니다. 기본은 한 번에 한 판이며, 추가 참가자 대기는 로비 서버의 `-wait` 옵션으로 조절합니다. 인게임의 `로비로 나가기` 버튼으로 다음 테스트를 준비할 수 있습니다.

드래그 박스에 몸통 중심이 들어온 내 유닛을 최대 64개 선택합니다. 일반 클릭·드래그는 이전 선택을 대체하며, 빈 박스는 선택을 해제합니다. Shift+클릭은 추가/제외, Shift+드래그는 새 유닛이 있으면 추가하고 박스 안이 전부 선택돼 있으면 제외합니다. 더블클릭은 화면 안의 같은 종류인 내 유닛을 선택하며, Shift+더블클릭은 기존 선택에 추가합니다. 드래그 중 Esc 또는 우클릭으로 취소할 수 있습니다.

Ctrl+1~9로 선택한 부대를 저장하고, 숫자로 다시 선택합니다. 같은 숫자를 빠르게 두 번 누르면 부대 중심으로 카메라를 옮깁니다. 미니맵 좌클릭·드래그는 카메라 이동, 우클릭은 선택 부대 이동이며 밝은 사각형으로 현재 카메라 범위를 표시합니다. 서버 변경 없이 기존 이동 명령을 사용합니다.

하단 미니맵과 명령 패널 사이에 높이 186px의 선택 상세정보를 표시합니다. 단일 선택은 이름·초상화·체력·행동 상태, 다중 선택은 개별 초상화·체력바를 보여줍니다. 초상화 클릭은 단일 선택, Shift+클릭은 제외, Ctrl+클릭은 같은 종류만 선택합니다. 많은 유닛은 페이지 버튼으로 확인하며 전체 선택은 유지됩니다.

선택 후 적 유닛·건물을 우클릭하거나 A를 누르고 적을 좌클릭하면 `ATTACK 대상ID 내유닛ID...`를 보냅니다. A를 누르면 십자 커서와 노란 공격 사거리 원이 표시되고, 한 번 클릭하거나 Esc를 누르면 종료됩니다. 영웅 모드는 내 영웅, 지휘관 모드는 선택한 내 유닛들의 사거리를 표시합니다. 원은 서버의 사거리와 유닛 충돌 반경을 사용하며, 적의 몸체가 원에 닿으면 사거리 안입니다. A 이후 빈 땅을 좌클릭하면 공격 이동(`ATTACK_MOVE`), 같은 진영 유닛·건물은 명령 없이 종료합니다. 땅 우클릭은 일반 이동입니다. 적 판정은 서버가 보낸 진영으로 구분하며 공격 판정은 서버에서 처리합니다.

건물을 좌클릭하면 유닛 선택이 해제되고 건물 체력바를 확인할 수 있습니다. 회관 2개와 요새 8개는 서버 배치대로 표시하며, 완성된 요새와 포탑의 조준·발사·피해·파괴는 서버 STATE/HP/REMOVE에 맞춰 반영합니다.

전장의 안개는 같은 진영 유닛·미니언·건물의 시야를 공유합니다. 나무·벽은 이동과 시야를 막고, 건물은 이동만 막습니다. 시야와 공격 사거리는 몸 가장자리 사이의 거리로 계산합니다. 건물 위치는 처음부터 알려져 있지만 적 건물의 조회·공격에는 현재 아군 시야가 필요합니다. 외벽이 시야에 들어오면 건물 모델 전체를 밝히고 주변 땅의 안개는 유지합니다. 적 유닛은 시야 밖에서 HIDE로 사라지고 다시 보이면 최신 상태로 등장합니다. 최신 서버와 클라이언트를 함께 사용하세요.

공격 버튼/A는 기존 공격 대상 지정, 정지 버튼/S는 현재 작업 중단 후 주변 경계, 홀드 버튼/D는 위치 사수입니다. 정지는 주변 적을 추격하고 돌아오며, 홀드는 사거리 안의 적만 공격하고 자리를 떠나지 않습니다. 작업 중단 시 운반 자원과 공사 부지는 유지됩니다. 클라이언트와 서버를 함께 갱신해야 합니다.

맵 카메라는 마우스를 화면 가장자리에 가져가거나 W/S(위/아래), Q/D(왼쪽/오른쪽), 방향키·가운데 드래그로 이동합니다. 휠로 확대/축소, Home으로 전체 보기이며, **Space는 영웅 모드에서 내 영웅 위치, RTS 지휘관 모드에서 내 진영 본진으로 이동**합니다. Space는 현재 줌과 선택을 유지합니다. 가장자리 이동은 창 밖·포커스 해제·마우스 드래그 중에는 멈춥니다. 내 유닛을 선택한 동안 S/D는 정지/홀드에 사용하므로 아래/오른쪽 카메라 이동은 방향키로 합니다. 늑대 AOS의 Q는 스킬에 사용하므로 왼쪽 카메라 이동은 방향키로 합니다. A는 공격 대상 지정에 사용합니다.

내 일꾼을 선택하고 **Z / 넘패드 1 위치의 1티어 버튼**을 누르면 건설 메뉴로 들어갑니다. Q는 저장소, W는 합숙소, E는 병영, A는 대장간, S는 포탑입니다. 메뉴가 열려 있는 동안 해당 키는 건설 메뉴에 사용합니다. [명령 패널](docs/command-panel.md)을 참고하세요.

건물을 고르면 반투명 미리보기가 나타나고, 지면을 좌클릭하면 `BUILD 건물타입 x z 일꾼ID`를 요청합니다. 회색 도로·벽·나무·건물·알려진 유닛과 겹치거나 맵 밖이면 빨간색과 사유를 표시하고 전송하지 않습니다. 초록색 빈 부지와 벌목이 끝난 자리에는 건설할 수 있습니다. [도로·건설 부지·초기 숲 배치](docs/map.md)를 참고하세요. 우클릭·Esc로 취소합니다. 타입 순서는 **회관 0, 요새 1, 저장소 2, 합숙소 3, 병영 4, 대장간 5, 포탑 6**입니다. 저장소는 `Store.tscn`/`store`, 대장간은 `Forge.tscn`/`forge`로 구분합니다. [건설 배치](buildings/README.md#건설-배치)를 참고하세요.

서버가 공사를 시작하면 건물 크기에 맞춘 공통 테두리와 글자 없는 중앙 팻말을 표시합니다. 진행률은 선택 상세정보 창에 표시하고, `CONSTRUCTION 건물ID 진행률`이 100이 되면 완성 모델로 바꿉니다. 내 일꾼을 선택하고 아군 공사 부지를 우클릭하면 한 명에게 `CONSTRUCT 건물ID 일꾼ID`를 보내 이어 짓습니다. 다른 건설자가 있는지는 서버가 판정하고 `ERR 이미 짓는 중`을 알립니다. 공사 중 건물도 파괴 시 즉시 제거합니다.

회관은 5×5, 석조 요새(`Fortress.tscn`, 타입 1)는 4×4, 목조 간이 포탑(`Tower.tscn`, 타입 6)은 3×3입니다. 요새는 시작 건물이고 간이 포탑은 목재 200·30초로 건설합니다. 기존 모델을 확대해 서버 점유 크기에 맞췄으며, 게임 속 건물의 정면은 플레이어의 카메라 방향을 향합니다. 서버 회전값은 입구 방향에만 적용하고 충돌·배치·공사 테두리는 서버와 같은 축 정렬 영역을 사용합니다. `previews/Buildings.tscn`에서 회관·요새·포탑을 같은 배율로 비교할 수 있습니다.

배치 미리보기는 시작 때 읽어 둔 투명 이미지를 재사용합니다. 버튼 클릭 시 모델을 생성하지 않고 위치·크기·색만 갱신합니다. 공사 부지는 공통 3D 표시를 쓰고, 완공 후에는 각 건물의 3D 모델을 표시합니다.

서버 없이 외형을 확인하려면 `previews/Units.tscn`, `previews/Trees.tscn`, `previews/Arena.tscn`, `previews/Forest.tscn`, `previews/TownHall.tscn`을 열고 F6으로 실행합니다. 합숙소·저장소·병영·대장간은 `previews/ProductionBuildings.tscn`에서 함께 보고 회전·확대할 수 있습니다. 저장소·합숙소는 3×3, 대장간은 병영과 같은 5×3이며 개별 미리보기는 `previews/Store.tscn`, `previews/Forge.tscn`입니다. 건물의 비용·공사·완공과 인구수, 회관·병영의 생산 대기열·취소·랠리를 서버와 동기화합니다. 저장소의 추가 반납·보관 경제와 대장간 제작 기능은 아직 없습니다. [건물별 영어 이름](buildings/README.md#영어-이름-추천)도 정리했습니다.

나무는 `resources/trees/Tree.tscn`을 Oak/Pine/Birch 씬이 상속합니다. 자원 ID와 선택 표시(`ResourceNode.cs`), 클릭 영역(물리 레이어 3)은 공통이며 `Visual` 아래 외형만 다릅니다. `VisualVariant`는 외형 번호로, 자원 종류나 채집 능력치를 구분하지 않습니다. 나무는 맵 파일에서 생성하며 서버는 남은 자원량과 제거 변경분만 보냅니다. 유닛 선택 후 나무를 우클릭하면 `GATHER 자원ID 내유닛ID...`를 보냅니다. 실제 채집 가능 여부는 서버가 검사합니다.

## 코드 역할

- `game/Main.cs`: PlayerInput 이벤트를 관리자에 연결하고, 서버 메시지를 분기합니다. 관리자가 요청한 명령을 NetClient로 전송합니다.
- `units/UnitManager.cs`: 유닛 목록, UNIT/POS/REMOVE 적용, 선택, 소유권 확인, MOVE/ATTACK/GATHER/BUILD/CONSTRUCT 명령 생성을 담당합니다. 생성한 유닛은 Main/Units 아래에 둡니다.
- `buildings/BuildingManager.cs`, `buildings/ConstructionSite.cs`: 건물 타입 0~6과 서버 공사 진행률을 반영하고, 공통 테두리·팻말과 완성 모델을 전환합니다.
- `resources/ResourceManager.cs`: 자원 ID별 나무 생성·갱신(`SpawnOrUpdate`), 조회(`TryGetResource`), 제거(`Remove`)를 담당합니다. 생성한 나무는 Main/Resources 아래에 둡니다.
- `units/Unit.cs`, `resources/ResourceNode.cs`: 유닛 한 개·자원 한 개의 ID와 화면 표시를 담당합니다.

맵은 `maps/MapWorld.cs`가 JSON에서 지형과 나무를 생성합니다. 서버와 SHA-256을 확인한 뒤 변경된 나무만 `TREE id amount`로 적용하며, 0이면 제거합니다. 맵 불일치 시 게임 진행을 막습니다. 양쪽에 같은 `maps/test.json`을 두세요.
