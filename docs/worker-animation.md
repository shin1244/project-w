# 일꾼 애니메이션

`previews/WorkerAnimations.tscn`을 열고 F6을 누르면 서버 없이 기존 일꾼 자세를 확인할 수 있습니다. 시추 작업·기름통 운반·기름 보유량은 `previews/OilGathering.tscn`에서 예시 메시지로 확인합니다.

| 클립 | 표시 조건 |
| --- | --- |
| Idle | 빈손으로 대기 또는 이동. 약한 호흡 동작 |
| Swing | 벌목·건설 중 반복. 공격은 실제 타격마다 한 번 |
| OilWork | 시추탑에서 작업 중. 도끼를 숨기고 천천히 수작업하는 자세 |
| Carry | 채집물을 들고 대기 또는 이동. 도끼를 숨기고 양팔로 통나무 또는 기름통 운반 |

다리와 유닛 루트 위치는 애니메이션으로 움직이지 않습니다. 작업 중에는 서버가 준 대상 ID로 유닛·자원·건물을 찾아 현재 위치를 바라보고, 그 외에는 이동 방향을 바라봅니다. 공격자가 서 있어도 대상의 POS만으로 방향이 갱신됩니다. 자원을 반납하면 Idle로 돌아가며, MOVE 등으로 채집 명령을 취소해도 아직 들고 있는 짐은 그대로 표시합니다. 공격 도중 자원을 들고 있었다면 휘두른 뒤 Carry로 돌아갑니다. 목재를 든 채 시추탑을 지정해도 반납 전까지 통나무를 기름통으로 바꾸지 않습니다.

## 구조

- `units/Worker.tscn`: 몸통·어깨 관절, 손에 붙은 도끼, 운반용 통나무(`CarriedWood`)·목제 기름통(`CarriedOil`), AnimationPlayer.
- `units/animations/Worker.tres`: Idle / Swing / Carry / OilWork 클립. Godot의 AnimationPlayer에서 편집 가능.
- `units/WorkerAnimation.cs`: 서버 상태를 보고 클립과 소품을 전환. 피해나 채집량을 계산하지 않음.
- `units/UnitState.cs`, `Unit.cs`: 유닛 공통 서버 상태와 대상 바라보기.
- `UnitManager.Resources`: 자원 ID 조회에 사용하는 관리자. Main 씬에서 Resources 노드에 연결합니다.
- `tools/build_worker_animations.gd`: 클립을 최초 값으로 다시 생성하는 도구. 실행하면 수동 편집한 클립을 덮어씀.

## 서버 연결

Go 서버의 `unit_state.go`가 상태가 바뀔 때만 아래 줄을 방송합니다. 입장 시에는 기존 유닛마다 UNIT 바로 뒤에 현재 STATE를 보냅니다. 공격 번호는 실제 피해 처리가 일어날 때만 증가하며, 중복 STATE나 첫 입장 스냅샷의 과거 공격은 다시 재생하지 않습니다.

```text
STATE 유닛ID IDLE|GATHER|ATTACK 운반량 대상ID 공격번호 [운반자원종류]
STATE 12 GATHER 0 700 0
STATE 12 IDLE 5 0 0
STATE 12 ATTACK 5 99 1
STATE 12 IDLE 5 0 1 2
```

유닛·자원·건물은 ID 공간을 공유하고, 대상 ID 0은 대상 없음을 뜻합니다. 마지막 자원 종류는 목재 0, 기름 2이며 생략된 기존 6필드 메시지는 목재로 처리합니다. 좌표를 상태 비교에서 제외했으므로 사거리 안에서 같은 적이 움직여도 STATE를 다시 보내지 않습니다. 대상 변경·실제 공격·운반량·운반 종류·행동 변화는 계속 전송됩니다.

클라이언트는 대상 노드를 캐시하고 작업 중 매 렌더 프레임에 방향을 갱신합니다. 입장 스냅샷에서 대상 UNIT이나 BUILDING이 나중에 도착하면 다시 조회하고 자세도 갱신합니다. 대상이 삭제됐거나 아직 없으면 마지막 방향을 유지하며, 다른 대상 ID로 바뀌면 이전 참조를 버립니다.

GATHER는 실제 채집 작업 시간에만 표시됩니다. 나무·시추탑까지 이동하거나 자리를 기다릴 때는 IDLE입니다. 운반량과 종류는 서버가 결정하며 클라이언트는 채집 속도·수량·반납을 계산하지 않습니다. 아직 대상이 도착하지 않은 채집 상태는 기름 종류가 확인되면 OilWork, 확인되지 않으면 대기로 표시합니다.

서버에서는 사망 즉시 게임의 유닛 목록에서 제거하되, 해당 틱의 REMOVE 알림은 POS → STATE → REMOVE 순서로 보냅니다. 마지막 공격의 대상 ID를 클라이언트가 조회할 수 있게 하기 위한 순서이며, 한 프레임 안에 두 메시지를 처리할 수도 있으므로 사망 연출 타이밍을 맞추는 기능은 아닙니다.

공격 판정 시간은 기존 서버 동작을 유지합니다. 공격 번호를 받은 후 0.8초짜리 도끼 애니메이션을 재생하므로, 현재 시각적 도끼 접촉과 서버 피해 발생 시점은 일치하지 않습니다. 선딜·타격 시점까지 맞추는 것은 이후 전투 애니메이션 단계에서 다룹니다.

클라이언트와 서버를 함께 빌드하고 서버를 재시작해야 새 STATE 메시지가 전달됩니다. 이전 좌표 형식의 STATE는 파서가 무시하므로 서버 실행 파일도 함께 갱신해야 합니다.

## 확인

외형과 팔 회전은 두 미리보기에서 확인합니다. STATE 종류·우클릭 명령·건설 전환은 `ConstructionSyncChecks`, 운반 표시·기름 보유량은 `SelectionDetailsChecks`와 `StockChecks`에서 검사합니다. 이 검사는 예시 서버 메시지를 사용하며 실제 채집·반납 결과는 별도 서버 저장소의 검증 범위입니다.
