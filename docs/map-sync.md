# 로컬 맵과 나무 변경분 동기화

클라이언트와 Go 서버에 동일한 `maps/test.json`을 둡니다. 파일은 원본 UTF-8 바이트의 SHA-256으로 비교하므로 공백이나 줄바꿈만 달라도 불일치합니다. 수정한 파일 하나를 양쪽에 복사하세요. 해시는 맵 버전 확인용이며 클라이언트의 정직성을 보장하는 보안 검증은 아닙니다.

`rows`의 `R`은 이동 가능한 건설 금지 구역이며 일반 도로뿐 아니라 중앙 이벤트 광장, 정글 공터·진입로, 상·하단 성곽 확장 부지의 진입로에도 사용합니다. 모두 같은 회색 도로 타일로 표시합니다. `.`은 확장 부지 내부를 포함한 건설 가능한 풀밭, `T`는 초기 나무 시작 칸, `W`는 이동·시야·건설을 차단하는 채집 불가 석벽, `#`은 맵 밖입니다. `R`은 서버의 이동·시야 장애물과 별도로 유지됩니다. 나무가 `R`에 걸친 맵은 로드 시 거부하며, 벌목 완료 후에는 나무 영역만 건설 가능해집니다.

선택적 `activityAreas` 배열은 `id`, `kind`, `center`, `radii`, `entrances`, `entranceWidth`로 이벤트·정글 구역의 의미와 스폰 기준점을 설명하며, 지면·미니맵 색상에는 관여하지 않습니다. 선택적 `expansionSites` 배열은 `id`, `center`, `buildSize`로 1팀 상단 (-34, -41)과 2팀 하단 (34, 41)의 6×6 건설 공터를 설명합니다. 두 멀티는 각 팀의 같은 라인에 있는 두 요새 사이에 연결되며, 원점 기준 180도 회전 대칭입니다. 주변 숲은 각 71그루이며 넓힌 진입로와 공터를 제외한 부지에 배치합니다. `LayoutGuides`에는 같은 이름의 마커가 생성되며 확장 마커 이름은 `team1_expansion`, `team2_expansion`입니다. 이동·건설 판정은 계속 `rows`를 따릅니다. 현재 마커는 이벤트나 몬스터 로직을 실행하지 않습니다. 두 메타데이터도 파일 해시에 포함되므로 양쪽 JSON을 함께 갱신해야 합니다. 자세한 좌표와 배치는 [맵 디자인](map.md)을 참고하세요.

클라이언트 `MapWorld`가 시작할 때 JSON을 읽어 `TerrainBuilder.gd`로 지형을 생성하고, `T` 칸마다 나무를 만듭니다. 미리 생성한 `.res` 파일은 게임 실행에 필요하지 않습니다. 나무 초기 자원량은 JSON의 `treeAmount`, 외형 번호는 `(열 + 행) % 3`입니다.

나무 ID는 시작 칸 기준 `행 * 맵 너비 + 열 + 1`입니다. JSON의 `treeSize`는 한 변의 칸 수이며, 생략 시 1입니다. 현재 맵은 2이므로 나무는 시작 칸에서 +X/+Z 방향 2×2 영역의 중앙에 배치합니다. 벌목 완료 시 네 칸을 모두 해제합니다. 서버의 유닛 ID는 전체 칸 수 다음 번호부터 사용하므로 나무와 겹치지 않습니다. 예를 들어 너비 8인 맵에서 시작 칸 (1,1)의 ID는 10입니다. 원점 (0,0), 칸 크기 1, treeSize=2이면 중심 위치는 (2,0,2)입니다.

현재 배열은 168×128칸, 원점은 (-84, -64)입니다. 중앙 상·하단 멀티를 요새 사이로 옮기는 이번 변경은 배열 크기와 원점을 유지하므로 기존 내부 나무 532그루의 좌표와 ID도 유지합니다. 멀티의 나무 배치와 맵 해시는 변경되므로 이전 맵의 변경 기록을 새 맵에 적용하지 않고, 동일한 새 JSON으로 서버를 재시작해 초기 상태부터 동기화합니다. 과거 성곽 확장 전의 168×92칸·원점 (-84, -46) 맵은 행 번호와 나무 ID도 다릅니다.

## 접속 순서

```text
서버 → MAP 2 <sha256>
클라 → MAP_READY <sha256> COMMANDER  # AOS는 HERO 200, 로컬 해시가 일치할 때만
서버 → TREE 4412 375          # 기본 상태에서 바뀐 나무만 (없으면 생략)
서버 → TREE 4580 0            # 0은 이미 제거된 나무
서버 → WORLD_READY
서버 → WELCOME <playerID> <team> COMMANDER  # HERO는 HERO <영웅종류>
서버 → UNIT ...              # 유닛은 기존과 동일하게 서버에서 생성
```

`2`는 나무의 점유 크기를 지원하는 맵 동기화 프로토콜 버전입니다. 해시 확인 전 서버는 플레이어 유닛을 생성하지 않고 게임 명령도 적용하지 않습니다. 클라이언트는 변경분 수신 완료 전 명령 전송을 막습니다. 맵 불일치는 화면에 표시하고 연결을 종료합니다.

`Main.RequestedRole`과 `RequestedHeroType`을 MAP_READY에 보내고 WELCOME을 받은 뒤 HUD를 전환합니다. `game/Main.tscn`은 COMMANDER, 같은 장면을 상속하는 `game/AOS.tscn`은 HERO 200을 요청합니다. 재동기화 때 확정된 역할·유닛·HUD 수치는 비우되 접속 요청값은 유지합니다. 현재 서버는 편마다 지휘관 1명·영웅 최대 4명을 배정하고, 지휘관에게 일꾼, 영웅 유저에게 선택한 영웅 1기를 생성합니다. 잘못된 영웅이나 만석은 ERR로 거절합니다.

플레이 중에도 `TREE <id> <남은 양>`을 보냅니다. 이 값은 감소량이 아닌 현재 남은 양입니다. 나무 위치·외형·전체 목록은 전송하지 않습니다. 서버는 제거 기록도 0으로 유지하여 나중에 접속한 클라이언트에 전달합니다. 재접속 시 로컬 나무를 기본 상태로 되돌린 뒤 현재 변경분을 적용합니다. 자동 재접속 UI는 아직 없습니다.

## 서버 채집 코드 연결

Go 게임 루프 안에서 다음을 호출합니다.

```go
taken := g.harvestResource(resourceID, 10)
gatherer.Carrying += taken
```

`harvestResource`는 남은 양만큼만 채집하고 변경 기록·방송·소진 시 격자 차단 해제를 함께 처리합니다. `r.Amount`를 직접 수정하거나 `g.resources`에서 직접 삭제하면 변경 기록이 빠지므로 이 함수를 사용하세요. 채집 가능 거리, 유닛 소유권, 작업 시간, 운반 한도는 이후 채집 명령에서 검사해야 합니다. 클라이언트의 나무 우클릭은 GATHER 명령으로 연결되어 있으며, 서버 GatherCommand/GatherOrder가 채집 행동을 처리합니다.

변경 기록은 현재 게임의 메모리에만 보관합니다. 서버를 재시작하면 맵 초기 상태로 돌아갑니다. 새로운 나무 심기나 재성장 메시지는 아직 지원하지 않습니다.

## 실행과 검증

JSON만 변경했다면 서버 프로젝트의 `maps/test.json`을 교체하고 서버를 재시작합니다. 서버는 시작할 때 파일을 읽으므로 맵 데이터 변경만으로 실행 파일을 다시 빌드할 필요는 없습니다. 서버 코드도 변경했다면 관련 검증 후 `go build -o project-w-server.exe .`로 빌드합니다. 실행 중인 exe는 먼저 종료해야 교체할 수 있습니다. 클라이언트는 C#을 빌드한 뒤 F5로 실행합니다.

이번 멀티 이전 후 지형 캐시를 재생성하고 서버 JSON도 함께 교체했습니다. 전체 맵과 멀티 근접 화면은 실제 GPU 렌더링으로 확인했습니다.

맵 관련 클라이언트 검증은 `./tests/run.ps1 -Suite World`로 실행합니다. `MapSyncChecks`는 고정 테스트 맵으로 해시 확인·자원량 갱신·제거·재접속을, `MapZonesChecks`는 건설 금지 구역·중앙과 정글의 도로색·확장 부지의 건물 면적 배치를, `FogSyncChecks`는 시야 동기화를, `check_arena.gd`는 생성 지형과 JSON 격자를 검사합니다. 기본 클라이언트 검증은 실제 서버 없이 실행합니다.

이번 멀티 이전 후 `./tests/run.ps1 -Check MapZonesChecks,check_arena`로 C# 빌드와 두 검증이 통과했습니다. 공터의 5×5 건물 배치, 주변 나무 차단, 원점 기준 회전 대칭과 실제 지형 충돌을 확인했습니다.

서버 프로젝트에서는 다음 관련 검증을 실행합니다. 현재 배치에서 네 검증이 통과했습니다.

```text
go test ./... -run "^(TestArenaBastionExpansionSites|TestArenaObjectiveAndJungleAccess|TestMapSync|TestFindPathTestMap)$" -count=1
```

`TestArenaBastionExpansionSites`는 두 성곽 확장 부지의 회전 대칭, 요새 사이의 접근 경로, 건설 가능한 면적과 일꾼의 실제 병영 건설 완료를 확인합니다. `TestArenaObjectiveAndJungleAccess`는 이벤트·정글 구역의 최소 전투 공간, 양쪽 입구의 골렘 통과, 대칭과 건설 금지를 확인합니다. `TestMapSync`는 실제 접속 초기화·변경 기록·늦은 입장을, `TestFindPathTestMap`은 현재 맵에서의 경로 탐색을 확인합니다.

Godot 게임을 내보낼 때는 비리소스 파일 포함 필터에 `maps/*.json`을 추가해야 합니다. `previews/Arena.tscn`은 편집용 캐시를 계속 사용하며, 갱신하려면 `tools/build_arena.gd`를 실행합니다.
