# 사망 연출과 명령 대상 표시

사망 연출은 서버의 `DEATH` 원인으로 고르고, 게임 판정은 서버가 그대로 맡습니다. 대상 원은 클라이언트만의 표시입니다.

## 사망

`REMOVE`를 받으면 유닛을 관리자 목록/선택/클릭 판정에서 즉시 제외하고 화면 모델만 남겨 사망 연출을 재생합니다. 서버는 유닛을 지우기만 하고, 연출은 클라이언트에서만 계산합니다. 어떤 연출을 쓸지는 서버가 `REMOVE` 직전에 보내는 `DEATH 유닛ID 원인`(마지막 타격의 무기, 서버 `docs/skills.md`의 사망 원인)으로 고릅니다.

| 넘어짐(원인 없음·사격) | 폭사(포격) |
| --- | --- |
| ![넘어지는 사망 연출](images/store/death-fall.gif) | ![폭사 연출](images/store/death-blast.gif) |

| 원인 | 마지막 타격 | 연출 |
| --- | --- | --- |
| `BLADE` 베기 | 일꾼·스팀돌격병·근접 미니언·늑대·사령관의 검 | 머리·팔·다리 중 무작위 두 곳(화염기계는 머리·노즐·궤도·바퀴 중 두 곳)이 쓰러지는 반대쪽으로 튀어 나가 바닥을 구르고, 나머지 몸은 옆으로 넘어집니다. 잘린 자리에는 불꽃만 잠깐 튑니다 |
| `SHOT` 사격 | 공압사수·치유사·원거리 미니언·레인저·사령관 권총·포탑·이동 모드 증기포격차 | 옆으로 넘어집니다(이전 연출) |
| `FIRE` 화염 | 화염기계 | 불티가 오르며 모델 전체가 검게 탄 뒤, 주저앉으며 재 무더기로 무너져 흐려집니다 |
| `BLAST` 포격 | 전개한 증기포격차·룬 골렘 | 모든 부위가 산산조각 납니다. 사람은 잿빛 먼지 속에 머리·팔·다리·몸통·무기가, 화염기계는 불덩이와 검은 연기 속에 머리·노즐·궤도·바퀴가 날아갑니다 |
| 원인 없음 | 환경 피해, 처형·소모, 접속 종료 | 옆으로 넘어집니다 |

- 부위 절단과 산산조각은 부품 노드가 정해진 일꾼·스팀돌격병·공압사수·화염기계와 근접·원거리·생명의 미니언에만 있습니다(`units/UnitBreakupEffect.cs`의 `Recipes`). 미니언의 방패·검·활·지팡이는 그것을 든 팔과 함께 떨어집니다. 다른 유닛은 같은 원인에도 넘어집니다. 재는 모델을 검게 칠하고 눌러 무너뜨리므로 모든 유닛에 씁니다.
- 쓰러지거나 흩어지고 나면 흐려지기 전까지 0.3초(`UnitDeathEffect.HoldSeconds`), 미니언은 0.1초(`MinionHoldSeconds`) 그대로 남습니다. 넘어짐은 0.45초 동안 넘어지고 그만큼 머문 뒤 0.45초 동안 흐려집니다. 베기는 잘린 부위가 구르는 모습이 보이도록 0.4초(`SeverHoldSeconds`, 미니언은 0.1초) 머뭅니다. 산산조각은 부품이 바닥에 멈출 무렵(사람 0.75초, 화염기계 1.05초)부터, 재는 재가 내려앉을 무렵(1.2초)부터 같은 시간을 센 뒤 흐려집니다.
- 피·상처·절단면은 그리지 않습니다. 블록 모델이 대량 생산된 인형처럼 부품째 떨어지는 것으로 "갈아 끼우는 사람"을 보여 주고([아트 디렉션](art-direction.md#인명경시-사람은-소모품-병기는-보물)), 기계는 더 크게 터져 대비를 만듭니다.
- 부품·재는 물리 몸체가 아니라 연출용으로 움직이며 클릭·충돌·시야에 영향을 주지 않습니다. 잘리는 부위와 흩어지는 방향은 유닛 ID로 정해 매번 같습니다. 루트 위치는 그대로라 사망 위치도 변하지 않습니다.
- 분해·재 연출이 이미 16개(`UnitDeathEffect.MaxActive`) 진행 중이거나 시야 밖에서 죽은 유닛은 넘어지는 연출을 씁니다. 큰 교전에서 화면이 부품으로 덮이지 않게 하기 위해서입니다.
- `DEATH`는 그 유닛이 살아 있을 때만 원인을 바꾸고 사망을 시작하지 않습니다. `REMOVE` 뒤에 온 원인은 무시합니다. 원인을 모르는 단어나 형식이 틀린 줄은 버립니다.
- 일꾼의 도끼질과 호흡은 사망 시작 때 정지합니다.
- 사망 중 추가 POS/STATE/REMOVE는 이동하거나 연출을 재시작하지 않습니다.
- 맵 초기화는 진행 중인 사망 연출까지 즉시 정리합니다.

연출 선택과 넘어짐은 `units/UnitDeathEffect.cs`, 부위 절단·산산조각은 `units/UnitBreakupEffect.cs`, 재는 `units/UnitBurnEffect.cs`, 메시지 해석은 `network/DeathSnapshot.cs`, 게임 오브젝트 제외는 `UnitManager.HandleRemove`, 클릭 차단은 `Unit.BeginDeath`에서 처리합니다. 타격과 사망 시점을 정밀하게 맞추는 서버 선딜 기능은 추가하지 않았습니다.

## 대상 원

`input/CommandTargetIndicator.cs`는 마지막으로 요청한 명령의 대상 한 곳을 표시합니다.

- 나무 우클릭/GATHER 요청: 노란 원.
- 적 우클릭 또는 A → 적 좌클릭/ATTACK 요청: 빨간 원.
- 원은 대상의 자식이므로 움직이는 적을 따라갑니다. 내 유닛의 초록 선택 원과 독립적입니다.
- 새 대상 명령, 이동 명령, 선택 변경, 대상 제거/나무 소진 시 이전 원을 지웁니다.

이는 클릭한 명령 대상에 대한 로컬 피드백입니다. 서버 승인 표시나 서버가 자동으로 다시 고른 모든 채집 대상을 표시하는 기능은 아닙니다.

## 확인

`previews/DeathEffects.tscn`을 열고 F6을 누르면 일꾼·스팀돌격병·공압사수·화염기계가 넘어짐과 폭사를 번갈아 반복합니다. README GIF로 찍는 방법은 [개발 안내](development.md#readme-교전-gif)에 있습니다. `previews/CombatFeedback.tscn`은 원인 없는 사망(넘어짐)을 반복하고, `-- --capture`로 실행하면 사망 0.525초 시점을 `docs/images/combat-feedback.png`에 저장합니다. 위쪽의 노란/빨간 원은 두 종류의 표시를 비교하는 독립적인 예시입니다.

`DEATH` 해석·원인별 연출 연결, 명령 대상·사망 후 조종 제외는 `./tests/run.ps1 -Check UnitSceneChecks`, 사망·HIDE 후 위치 반영 중단은 `-Check InterpolationChecks`에서 확인합니다.
